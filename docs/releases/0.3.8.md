# SaberOps v0.3.8

Released 2026-10-10. Preview software; interfaces and provider integrations can change.

## What changed

- Separate Chat and Work with a consistent composer, repository folders, distinct
  conversation names and counts. Turning a chat into Work keeps the original and
  creates a linked Work thread. Model selection, supported attachments, Send/Stop
  controls and native consoles remain in the shared application shell.
- Parallel Work: the orchestrator proposes two to six tasks with dependencies and
  file ownership; up to four workers execute together in isolated Git worktrees.
  Stable ordered integration and a final parent gate/review produce one candidate.
- Git & threads pane tracks task status, dependencies, branches, commits, owned
  files and consoles. Internal worker candidates cannot be accepted separately;
  publication and acceptance verify their provenance and actual Git merge parents.
- Team-aware run reports include child dispatches, gates, reviews and preserved
  partial work. Bounded failure excerpts retain the end of long check logs.
- Antigravity large prompts use stdin above the argument safety threshold, keeping
  complete review diffs. Model effort suffixes are respected unless explicitly
  overridden. Read-only review and terminal completion checks remain enforced.
- Native session ownership, takeover, saved history and fixed-source verification
  improvements accumulated since v0.3.7. Work exposes authority settings, resume
  information, structured review findings and Diagnostics for server identity.
- OmniRoute support as an OpenAI-compatible provider, UI presentation polish, and
  removal of superseded experimental code and orphaned routes.
- Corrected a stale Claude shared-chat permission assertion. The runtime recipe
  is unchanged: restricted local read tools, two governed channel tools and no
  permission bypass. Ordinary read-only native resume remains in plan mode.

## Upgrade

From a clean existing clone:

```bash
git fetch origin --tags
git switch --detach v0.3.8
python3.12 -m venv .venv
.venv/bin/python -m pip install .
.venv/bin/orch --help
```

Stop the old UI process before starting the upgraded one. Keep the same profile
and configured state paths to retain setup and history. Do not delete databases,
profiles or managed worktrees to upgrade. Back up existing state before upgrading;
additive database tables are created when needed, and old run policies remain
frozen. Switching profiles selects a separate workspace and can appear empty.
A downgrade is not a promised database migration path.

Launch with `orch ui --host 127.0.0.1 --port 8765 --profile YOUR_EXISTING_PROFILE`.
For development, install `.[dev]` and use the repository's gate scripts. Python
3.12 or newer and authenticated supported provider CLIs are required for their
respective native integrations.

## Using this release

- [Chat and Work guide](../chat-and-work.md): separate conversations, linked Work,
  model selection, attachments and Git acceptance.
- [Parallel workflow guide](../parallel-work.md): empty-project setup, dependencies,
  isolated branches, ordered integration, recovery limits and upstream attribution.
- [Operating notes](../operations.md) and [Session architecture](../session-architecture.md):
  routing, native controls and verification boundaries.

Configure a real executable gate before launching work. An installed CLI is not
proof of access to the selected model; verify it in Connections. Parallel workers
add model calls, gates and reviews, and the final parent adds an integration
worker and full verification. Budget accordingly.

## Limits and validation

Git conflicts stop integration and preserve branches. Automatic conflict repair
and automatic replay of interrupted teams are not implemented. File ownership
checks constrain submitted candidate changes; they are not an operating-system
sandbox. Acceptance remains governed by the selected authority mode and its
verification requirements. This release adds no automatic GitHub publication
command for accepted project work.

Live validation completed a four-task ParallelBoard team with concurrent backend
and frontend workers, all child gates/reviews, 72 application tests, a final
independent review using a 114,537-byte prompt, and 11 browser check groups.
The candidate remained unaccepted and the source project stayed unchanged.
This validates the tested provider accounts and CLI versions, not every adapter.

- Full release gate: Ruff passed, strict mypy passed across 238 source files,
  and all 912 tests passed (732.54 seconds). The suite emitted 857 dependency/API
  deprecation warnings; no tests failed or were excluded.
- Wheel built and installed outside the checkout: version metadata, imports,
  CLI help, every Jinja template and new UI assets verified. No runtime databases
  or bytecode caches were included.
- Dashboard and Work/Git views checked at 1161 and 390 pixels; light and dark
  themes inspected with no page errors or horizontal page overflow. Changed
  application JavaScript passed syntax checks.
