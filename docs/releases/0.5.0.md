# SaberOps v0.5.0

Released 2026-10-20. Preview software; interfaces, storage schemas and provider
integrations can change.

v0.5.0 makes SaberOps a one-time setup: a redesigned local web UI where routing
is chosen and changed on the page, an Accounts page for subscription usage and
billing, and one command to connect SaberOps to your coding agents.

## Highlights

- **New web UI.** One calm "framed sheet" design across Runs, run detail,
  Questions, Routing, Accounts, Projects and Setup, in light and dark, usable on
  a phone. Plain language on screen; engine ids, paths, SHAs and codes sit
  behind "Technical details". View transitions between pages, with reduced
  motion respected. IBM Plex Sans is bundled (SIL OFL), so nothing loads from
  the network.
- **Routing in the UI.** Five jobs in work order (Plans, Writes, Checks,
  Repairs, Combines), one changed at a time: put a model in charge, add
  backups, reorder, remove. The picker offers only models with fresh,
  discovery-verified evidence and an exact binding that resolves, ten per page,
  with account tabs and search by model or provider ("opencode go"). Each model
  shows where it comes from ("OpenCode Go · via OpenCode"). Out-of-date model
  lists are named with an in-place Refresh.
- **Accounts page.** Per subscription (Codex, Claude, OpenCode Go, Antigravity):
  how much of each 5-hour, weekly and monthly window is left, with reset times,
  read from each CLI's own usage metadata (no prompt sent); billing type and
  confirmation with one-click "Confirm all".
- **Connect any agent.** `orch connect [claude|codex|antigravity|opencode|cursor|all]`
  (or Setup → Connect) registers `orch mcp serve` with each agent's own MCP
  settings; `--project`, `--remove`, `--dry-run`.
- **SaberOps on demand in the agent.** Every agent session starts with SaberOps
  off and works as a normal agent; say "turn on saberops" / "turn off saberops"
  (`saberops_on` / `saberops_off`). Everything SaberOps says starts with
  `Orchestrator:`. `orch mcp on|off|status` is the owner's switch for every
  agent. A built-in guide (instructions, `saberops-guide` prompt,
  `saberops://guide` resource) teaches any agent the workflow.
- **The planning agent is named.** The MCP lease records the connected client,
  shown on Routing and Setup.

## Behaviour changes

- **Fresh installs route nothing** until you choose models on the Routing page.
  Existing routing files are untouched.
- **Billing confirmations no longer expire** by default; a confirmation holds
  until you change it. Billing types are still enforced (attended-only and
  forbidden stay so). `orch posture verify SELECTOR --ttl-days N` (1-90) opts a
  route back into expiry.
- **Model lists refresh themselves**: on `orch ui` start and daily, any account
  whose list is missing, out of date or older than a day is re-listed
  (`SABEROPS_NO_AUTO_REFRESH=1` turns this off).
- **OpenCode listing** runs on a private server (`opencode models --standalone`,
  fixing failed refreshes with OpenCode v2) and lists every provider the account
  reaches; each run stays pinned to its own provider for billing.
- "Ready for billing" now counts attended-only and pay-per-use confirmations as
  confirmed.

## Install or upgrade

```bash
uv tool install git+https://github.com/sabers13/SaberOps.git@v0.5.0
# or: pipx install git+https://github.com/sabers13/SaberOps.git@v0.5.0
orch ui            # http://127.0.0.1:8765, Setup walks through the rest
orch connect all   # register SaberOps in your agent CLIs
```

Upgrading: stop any running `orch ui` first, then restart it. Existing state,
routing and confirmations are kept; press **Confirm all** on Accounts once to
make older 30-day confirmations permanent.

## Validation

- `bash scripts/gate-full.sh` on the release tree: Ruff passed; strict mypy
  passed; see the release commit for the test totals.
- As in v0.4.0, `tests/test_gate_tools.py` tests that launch the gate-slot
  helpers can time out under the gate's own parallel pass and are reported as
  unquarantined flaky tests; they pass on rerun and CI's serial `pytest -q` is
  unaffected. Known gate-tooling issue, tracked for a follow-up.
- orch-UI checks on every screen: taste lint and inspector (0 FAIL), screenshots
  at 375/768/1440 px in light and dark with no overflow or console errors.
- Tests and CI make no provider or model calls; agent CLIs, model listings and
  usage readers are exercised through fakes and recorded fixtures.
